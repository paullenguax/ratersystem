# Assignments  *(admin)*

An assignment is the unit of marking work: a session + a rater + a set of
tests + a status. This is where marking is set up, monitored, published and
reviewed.

## Creating assignments

- **By hand**: pick the session, the rater, and the tests.
- **Auto‑assign** (Admin → Auto‑assign): spreads tests across the raters in
  a session in a balanced way, avoiding tests a rater has seen before.
- **Self‑serve**: a trainee going through `/take-test` gets a 4‑test
  assignment built for them with no admin setup.

## Status vs confirmed

Two different things:

- **Status → submitted**: all tests now have a score. This does *not* mean
  the rater is finished.
- **Confirmed**: the rater has clicked "Yes, that's my scores" on their
  review screen. Only then is it truly done, and only then are you notified.

Wait for **confirmed**, not just submitted.

## Publishing

For rater‑course assignments, **Publish** makes the scores official and
visible in **Scores**. Standardization assignments have no publish step —
their scores are live as soon as they're saved, so the Publish button is
hidden for them.

## Reviewing

**View** on an assignment opens a per‑test breakdown. For a test given to
more than one person it shows each person's scores side by side with mean
columns — this is how you compare raters on the same recording.
